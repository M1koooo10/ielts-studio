# IELTS Studio · Фаза 1

## Вход в текущей версии

На экране входа нажмите «Создать аккаунт», выберите страну и введите номер телефона и пароль от 8 до 128 символов. Укажите имя при первом входе. В следующих сеансах используйте тот же номер и пароль. Номер служит идентификатором аккаунта. Для регистрации и входа больше не нужна настройка Twilio. При обновлении существующей базы выполните `npm run db:migrate`.

Локальное рабочее пространство для персональной подготовки к IELTS Academic. Интерфейс на русском, учебные задания на английском. На первом этапе можно настроить профиль и сессию, посмотреть материалы и открыть обзор с данными из SQLite.

## Запуск

Понадобятся Node.js 22.13+ и npm. На Windows при ограничении PowerShell используйте `npm.cmd` вместо `npm`. Выполняйте команды из каталога с `package.json`.

```sh
npm ci
npm run db:migrate
npm run dev
```

Откройте [локальное приложение](http://127.0.0.1:3000). При первом запуске на обзоре выберите **Начать подготовку** для подключения своего ключа OpenAI или **Войти без AI**. Для готовой production-сборки выполните `npm run build`, затем `npm start`. Сервер слушает только петлевой адрес. Остановить его можно клавишами Ctrl+C.

Для запуска после установки интернет нужен только при обращении к OpenAI. Иллюстрация, стили, шрифтовой стек, материалы и база находятся локально. Публичное размещение и многопользовательский доступ выходят за рамки этой версии.

## Что доступно

- Обзор показывает минуты за 7 или 30 дней, серию занятий, цели, план, результаты и последние события из базы. Чистая установка содержит нулевую активность и пустые оценки. Просмотр материалов сам по себе не создаёт попытку.
- Настройки сохраняют имя, целевой Band, дату экзамена, минуты в день, тему, язык объяснений, модель и предпочтение озвучивания. Системная тема реагирует на настройки устройства.
- В библиотеке доступны четыре авторских материала. Есть фильтры и просмотр полного текста, инструкций и вопросов. Ответы и доказательные фрагменты хранятся на сервере.
- У каждого раздела есть адрес и состояние доступности. Навигация сворачивается на компьютере. На телефоне работают нижняя панель и меню с поддержкой клавиатуры.
- Доступ к библиотеке находится в настройках. Аватар подключается файлом `public/avatars/ai-teacher.png`. При его отсутствии отображается нейтральный знак. Инструкции находятся в `public/avatars/README.md`.

## Сессия AI

Форма очищает поле ключа при отправке. Сервер через официальный OpenAI SDK вызывает `models.list()` и принимает ключ после успешной проверки. Требуется разрешение провайдера на чтение списка моделей. Внешний запрос передаёт ключ только OpenAI. Логи SDK отключены. Изменяющие запросы проверяют Origin и Host, а запись настроек дополнительно требует локальную или подключённую сессию.

Ключ живёт в памяти одного процесса Node.js. В браузере остаётся случайный идентификатор в сессионной HttpOnly-cookie с SameSite=Strict. При HTTPS выставляется Secure. Отключение и успешная замена ключа аннулируют прежний идентификатор. Изменение ключа с неуспешной проверкой сохраняет текущее подключение.

После 30 минут бездействия сессия недействительна. Фоновая очистка проходит раз в минуту. Перезапуск Node.js забывает все сессии и ключи. Новый браузерный сеанс требует повторного подключения для AI. Браузеры с восстановлением окон иногда восстанавливают и сессионные cookies. Для немедленного завершения AI-сессии используйте **Отключить**.

Локальный запуск не требует переменных окружения. При использовании собственного HTTPS-прокси `STUDIO_ORIGIN` задаёт точный HTTPS origin; прокси должен сохранить исходный Host. Не используйте журналирование тела запросов на прокси. Оплата API относится к аккаунту пользователя у провайдера. Чат, голосовые вызовы и учёт токенов запланированы на фазу 4.

## Хранилище, контент и резервная копия

По умолчанию файл базы находится в `data/studio.sqlite`. Можно задать иной путь переменной `STUDIO_DB_PATH`. Drizzle использует локальный SQLite-драйвер libSQL. При первом открытии сервер применяет недостающие файлы из `migrations/`. Каждая миграция и запись о ней выполняются в одной транзакции. Повторный запуск сохраняет существующие данные.

В `0001_workspace.sql` находятся профиль, настройки, цели, версионируемые материалы, вопросы, ключи, попытки, снимки ответов, оценки, события и задания плана. В `0002_seed.sql` находятся исходные материалы. Для новой поставки контента добавьте следующую нумерованную SQL-миграцию по этому образцу, проверьте её на копии базы, затем запустите `npm run db:migrate`. Каждый SQL-оператор отделяется строкой `--> statement-breakpoint`. Для исправленного материала создайте новую версию с прежним slug. Библиотека выбирает последнюю готовую версию. Редактор, загрузки и валидируемый JSON-импорт/экспорт относятся к фазе 2.

```sh
npm run db:backup
```

Команда создаёт согласованный снимок SQLite через `VACUUM INTO` и выводит путь к файлу в подкаталоге `backups` рядом с рабочей базой. Для восстановления остановите сервер, сохраните исходный каталог данных целиком и скопируйте снимок в новый каталог под именем `studio.sqlite`. Укажите путь к этой копии через `STUDIO_DB_PATH` и запустите сервер. Сессии и ключи OpenAI в снимок не входят.

## Проверка

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

Vitest проверяет проверку ответов стартовых типов, ограничения по словам, миграции, повторное открытие файла, сохранение настроек, расчёты обзора и жизненный цикл сессий. В модульных тестах проверка ключа заменяется тестовым провайдером. В приложении используется официальный сервис OpenAI.

Playwright поднимает production-сервер на порту 3417 с отдельной тестовой базой. На Windows используется установленный Google Chrome, если он доступен по стандартному пути. Можно передать путь к совместимому браузеру через `STUDIO_TEST_BROWSER`. Иначе установите Chromium командой `npx playwright install chromium`. Для E2E требуется свежая production-сборка.

## Входная диагностика

После заполнения профиля приложение направляет ученика на обязательную четырёхчастную диагностику. Страница `/placement` восстанавливает ранее сохранённый этап. После завершения она показывает результат. Кнопка Start My Learning Journey записывает план и открывает кабинет.

Для 0–10 правильных ответов в Listening используются предварительные баллы 1, 2, 2.5, 3, 3.5, 4, 4.5, 5, 5.5, 6, 7. Для Reading используются 1, 2, 2.5, 3, 3.5, 4, 5, 5.5, 6, 7, 8. Это авторские шкалы коротких наборов без экзаменационной калибровки. В Writing каждое задание оценивается по четырём критериям, второе имеет двойной вес. Speaking оценивается по трём аудиозаписям. Общая оценка появляется после проверки всех четырёх навыков и округляется до полубалла.

Локальная проверка и составление плана работают без ключа. На странице результата ученик может подключить OpenAI и отправить свои ответы на проверку. Для Writing используется текстовая модель из настроек, для Speaking по умолчанию используется `gpt-audio`. Имя совместимой модели с приёмом WAV можно задать на сервере через `STUDIO_PLACEMENT_AUDIO_MODEL`. Если оценивание недоступно, ответы сохраняются для повторной отправки.

Вопросы, тексты и задания находятся в `src/lib/placement`, записи для Listening — в `public/content/placement`. Экран теста, запись голоса и действия на странице результата находятся в `src/features/placement`, сохранение и оценивание — в `src/server/placement`. Маршруты расположены в `src/app/placement` и `src/app/api/placement`, структура данных задана миграцией `0018_placement.sql`. Проверка входа в кабинет, прежняя страница тестов и карточка на главной связаны с новой диагностикой.

## Модули

| Расположение | Назначение |
| --- | --- |
| `src/app` | App Router, страницы, маршруты API, состояния загрузки и ошибок |
| `src/components` | Оболочка, навигация, доступные UI-примитивы |
| `src/features/dashboard`, `practice` | Обзор, карточки навыков, график, просмотр материалов |
| `src/features/settings`, `library` | Формы, онбординг, подключение AI, библиотека |
| `src/lib` | Общие контракты Zod, навигация, базовая логика проверки ответов |
| `src/server/db`, `migrations`, `scripts` | Доступ к SQLite, миграции, авторские материалы и резервирование |
| `src/server/ai` | Проверка запросов, сессии в памяти и адаптер провайдера |
| `tests` | Vitest и сквозные браузерные тесты |

## План итераций

1. **Основание.** Локальный сервер и данные, сессии, оболочка и маршруты, контроль качества. Реализовано в данной итерации.
2. **Учебный движок.** Добавить группы вопросов Reading и виджеты всех требуемых типов, ограничения ответа и правила оценки. Реализовать Listening с оригинальным аудио, сегментами расшифровки и режимами Practice/Exam. Сохранять и восстанавливать попытки, таймеры, пометки и ответы, показывать неизменяемый разбор. Расширить библиотеку редактором, загрузками и валидируемым JSON. Разблокировать экзаменационные варианты только после проверки комплектности.
3. **Writing и Speaking.** Черновики и версии, задания, таймеры и запись микрофона.
4. **AI.** Оценивание, транскрипция, диалоги, голосовые уроки и рекомендации.
5. **Персональное обучение.** Курсы грамматики, интервальные карточки, планировщик, журнал ошибок, расширенная аналитика и игры.
6. **Интеграция.** Расширенные E2E-проверки, доступность, восстановление данных и профилирование.
